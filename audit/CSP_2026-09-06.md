# CSP·보안 헤더 적용 (2026-09-06 · v229)

> 기준 cc73951 · 작업트리 `review/doc-claims-10`. CSP 부재 자체를 취약점으로 보지 않았다(`SECURITY_INPUT` §5 강화 후보) — 실제 배포 헤더와
> 외부 자원을 확인한 뒤 **작고 안전한 변경으로 실효성 있는 정책**이 되는 경우에만 적용했다. 도구 `deploy/csp_inject.py` · 회귀 `audit/test_screen8.py` C1.

## 1. 실제 배포 헤더 (curl -sI · 사이트 루트·guide·data/signal.json·manifest)
`HTTP 200 · Access-Control-Allow-Origin: * · Strict-Transport-Security: max-age=31556952 · Cache-Control: max-age=600` — **CSP·X-Frame-Options·Referrer-Policy·Permissions-Policy 없음.**
GitHub Pages 는 응답 헤더를 바꿀 수 없다 → 가능한 것은 문서 안 `<meta http-equiv="Content-Security-Policy">` 뿐(frame-ancestors·report-uri 는 meta 로 못 건다).

## 2. 외부 자원·통신 대상 전수 (세 화면 소스 grep + 실행 실측)
| 종류 | 대상 | 정책 |
|---|---|---|
| 스크립트 | 인라인 `<script>` 만 — signal 2 · guide 1 · notes 1. 외부 `src` 0 · `eval`/`new Function` 0 · `javascript:` 0 | 해시 허용(`'sha256-…'`) |
| 인라인 이벤트 핸들러 | signal 1곳(검증 배지 `onerror`) → **리스너로 옮김**(v229) · guide/notes 0 | 없음 → `'unsafe-hashes'` 불필요 |
| 스타일 | `<style>` + `style=` 속성 83곳 · Pretendard CSS(`cdn.jsdelivr.net`) | `'self' 'unsafe-inline' https://cdn.jsdelivr.net` |
| 폰트 | jsdelivr(Pretendard 가변) | `font-src https://cdn.jsdelivr.net` |
| 이미지 | 아이콘(self) · GitHub 검증 배지 SVG(`github.com`) · `data:` 0(허용은 둠) | `img-src 'self' data: https://github.com` |
| fetch | `data/*.json·csv` 같은 오리진뿐(raw.githubusercontent 등 0 · v176 기각 그대로) | `connect-src 'self'` |
| 매니페스트 | `manifest.json` | `manifest-src 'self'` |
| 나머지 | `<form>` 0 · `<iframe>` 0 · 워커 0 · 플러그인 0 | `default-src 'none'; base-uri 'none'; form-action 'none'; object-src 'none'; frame-src 'none'` |
| 외부 링크(구글 파이낸스·네이버) | 탐색이라 CSP 대상 아님 | — |

## 3. 왜 배포 때 넣는가 (설계)
- `stamp_rev.py` 가 배포 때 스크립트 안의 `HTML_REV` 를 치환한다 → 해시는 **치환 뒤 배포본**에서 계산해야 맞다(셀프테스트가 치환 전후 해시가 다름을 고정).
- 소스·로컬 사본(file:// · v141 비상 판정)에는 CSP 가 없다 — 편집이 정책을 깨뜨릴 일이 없다. 잠기는 것은 배포본뿐.
- **실패 규약(fail-open)**: `csp_inject.py` 는 인라인 핸들러·외부 `src`·스크립트 없음이면 정책을 넣지 않고 실패하고, pages.yml 스텝은 `|| echo ::warning` 으로 **CSP 없는 종전 배포본**을 내보낸다 — 화면을 얼리지 않는다(v137 원칙).
- 소스에 인라인 핸들러·외부 스크립트가 생기면 `test_screen8.C1`(CI)이 먼저 잡는다.

## 5. 적용 범위와 남은 것
- 적용: `deploy/csp_inject.py`(새 파일 · `--selftest`) · `pages.yml` 스텝 1(도장 뒤) · `signal.html` 배지 핸들러 → 리스너 · 회귀 C1(소스 3화면 해시 정책 수용·셀프테스트·스텝 순서·fail-open).
- **실효성**: 주입된 스크립트 실행·타 오리진 유출(fetch/XHR/beacon)·외부 스타일·폼·프레임을 막는다. 못 막는 것: `location=` 탐색으로의 유출(navigate-to 미지원) · 스타일 주입(`'unsafe-inline'`) · 클릭재킹(frame-ancestors 는 헤더 전용 — Pages 에선 불가).
- 배포 뒤 확인 항목: 라이브 루트에 meta 존재 · 라이브 콘솔 위반 0(정상 사용) — 아래 §G.
- 제안만: 리퍼러 정책(`<meta name="referrer" content="no-referrer">` — 외부 링크로 나갈 때 URL 유출 방지 · 소유자 판단) · 헤더가 필요한 항목(frame-ancestors·HSTS preload)은 호스팅 이전 없이는 불가.
