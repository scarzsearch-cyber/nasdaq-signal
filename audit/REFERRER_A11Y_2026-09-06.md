## ① 리퍼러 정책
### 1. 현재 배포의 실제 정책과 경로
- 배포 헤더(`curl -I` 사이트 루트): `Strict-Transport-Security` 뿐 — **Referrer-Policy 헤더 없음**. GitHub Pages 는 응답 헤더를 설정할 수 없으므로 헤더 방식은 불가(설정된 것처럼 적지 않는다). 따라서 정책은 **브라우저 기본값 `strict-origin-when-cross-origin`** 이었다.
- 세 화면의 바깥 경로: 바깥 링크(신호 스트립 3 · 종목 행 `.ext` 4 · 설명서 상단 3)는 전부 `target=_blank rel="noopener noreferrer"`(v198) · 신호 stale 배너의 Actions 링크 2(`rel=noopener` 만) · 폰트 CDN `cdn.jsdelivr.net`(CSS+글꼴) · 검증 배지 `github.com/…/badge.svg`(img) · 데이터 fetch 는 전부 같은 오리진 `data/*` · `navigator.share({url})`·`{files}` 는 리퍼러와 무관 · 노트는 바깥 링크 0.
### 2. 합성 URL → 로컬 수신 지점 실측 (`pb/ref/recv.py` · 페이지 오리진 `localhost:8021` · 교차 오리진 `127.0.0.1:8022` · 실제 화면 아님)
페이지 URL `…/a.html?q=QUERY123#hash=SYNTHHASH`. 수신기가 `Referer`·`Origin`·`Sec-Fetch-Site` 를 기록.
| 요청 | 기본 정책(A) 의 Referer | `<meta name="referrer" content="no-referrer">`(B) |
|---|---|---|
| 교차 오리진 이미지 · fetch · 같은 탭 링크 | `http://localhost:8021/` — **오리진만**(경로·쿼리 없음) | 없음 |
| 같은 오리진 fetch · 이미지 · 링크 | `http://localhost:8021/a.html?q=QUERY123` — 경로+쿼리 | 없음 |
| `rel=noreferrer` 링크 | 없음 | 없음 |
| **해시 `#hash=…`** | **어디에도 전송 안 됨**(A·B 동일) | 없음 |
| CORS fetch 의 `Origin` 헤더 | 있음 | 있음(CORS 필수 · 정책과 무관) |
(`target=_blank` 링크는 이 브라우저 창이 새 탭 대신 같은 탭으로 열어 `Sec-Fetch-Site: none` 으로 기록됐다 — 일반 브라우저에서는 기본 정책상 오리진만 간다.)
### 3. 판단·적용
- 기본 동작만으로도 **경로·쿼리·해시는 바깥으로 안 나간다**. 남는 노출은 **오리진 `https://scarzsearch-cyber.github.io/` = GitHub 계정명**이 jsdelivr(폰트 요청마다)·github.com(배지)·Actions 링크에 전달되는 것.
- 명시 정책 `no-referrer` 는 그 오리진 전송까지 없앤다. 기능 의존 확인: jsdelivr 글꼴·GitHub 배지·네이버/구글 링크·같은 오리진 fetch·공유·백업 링크 모두 Referer 를 요구하지 않는다(B 페이지에서 이미지·fetch 정상 수신 · 배포본 라이브에서 글꼴·배지 요청 성공 — §5). CSP 와는 독립(리퍼러는 CSP 지시어가 아니다 · `csp_inject` 의 해시는 script 만).
- **적용(v231)**: 세 화면 `<head>` 에 `<meta name="referrer" content="no-referrer">` 한 줄 — 호스팅이 지원하는 최소 변경. 헤더 방식은 불가로 기록. `rel=noreferrer` 를 stale 배너 링크에 더 붙이지는 않았다(meta 가 덮는다 · 화면 문자열 최소 변경).
