## 1. 갱신 순서·실패·복구 — 재현과 판정 (signal.html)
| 시나리오 | 방법 | 수정 전 | 수정 후 |
|---|---|---|---|
| **느린 옛 응답이 새 응답 뒤에 도착**(탭 복귀 + 5분 ticker 겹침) | `fetch` 를 대역으로 바꿔 `price.json` 첫 요청은 400ms 뒤 10:05 스냅샷, 둘째는 즉시 10:10 → `refreshPrice()` 둘을 20ms 간격으로 | **PRICE 가 10:05 로 되돌아감** — 배지 「38,000원 · 10:05 시세」·placeholder 38,000(최신은 38,900 · 10:10) | 10:10 유지 · 배지 38,900 |
| 서버가 더 옛 스냅샷을 돌려줌 | 10:10 뒤 10:05 응답 | 10:05 로 후퇴 | 10:10 유지(단조) |
| 뒤늦은 실패가 새 성공을 지움 | 첫 요청 300ms 뒤 reject · 둘째 즉시 성공 | PRICE=null 로 초기화 | 성공 유지 · 최신 요청 자체의 실패만 null(v202 규약 유지) |
| 오프라인 → 복구 | price 요청 reject → `refreshPrice` → 다시 성공 | 시세 없음 → 배지가 장부 종가로 물러섬(「09-04 종가」 라벨 · v223) → 복구 시 시세 복귀 | 동일(정상) |
| **숨겨 둔 탭으로 복귀 — 신호** | `visibilitychange` 를 visible 로 흉내 · `signal.json` 대역이 2026-08-28 자 신호를 돌려줌 | **시세만 다시 읽고 판정·낙폭·신선도 점(초록)·「N거래일 지났습니다」 배너가 처음 값 그대로** — 금요일 탭을 화요일에 보면 낡은 판정이 최신처럼 | 새 종가면 부팅과 같은 경로(`redraw`)로 다시 그림(입력 「34」·포커스 보존 실측) · 같은 종가면 신선도 점·배너만 지금 시각으로 다시 잼(6거래일 → 빨간 점 + 배너) · 조회 실패면 화면 유지 |
| 일부만 새 버전 | 시세 새 + 장부 옛 / 그 반대 | `curPx` 가 「더 최신」을 고르고 출처 라벨을 붙인다(v179·v223) — 서로 다른 기준이 라벨 없이 섞이는 자리 없음 | 확인만 |
| 자동 갱신 vs 수동 입력 | 수량 입력 중 `redraw()`·`refreshPrice()` | 값·포커스·DOM 노드 보존 | 확인만(v173 유지) |

수정: `loadPrice` 요청 순번 + 스냅샷 시각 단조 + 뒤늦은 실패 무시 · `recheckSignal()`(탭 복귀 · 재진입 금지) · `paintAsof()` 공용화. 회귀 D1.

## 2. 브라우저 저장·복원 경계 — 재현과 판정
| 경우 | 방법 | 수정 전 | 수정 후 |
|---|---|---|---|
| **저장 공간 사용 불가**(시크릿·차단) | `localStorage` 게터가 SecurityError 를 던지는 사본(`_lsfail.html`) | 화면 정상 · 입력하면 「입력이 이 기기에 저장되지 않습니다」 배너 · 오류 0 | 동일(정상 · v116) |
| **잘못된 저장값(모양)** — `b_port_v1='[]'` · `b_trades_v1='{}'` · 수동 행 `{}` | 값을 넣고 재로드 | **포트폴리오 패널 0행 + 「화면 스크립트 오류」 배너 · 새로고침·캐시 삭제로 안 풀림**(값이 남아 매번 재발) | 패널 5행 정상 · 손상값은 `<키>_bad` 로 격리 · 배너 「저장된 보유 입력·체결 기록을 읽지 못해 비웠습니다 — 파일에서 복원」 · 이후 입력이 정상 저장 |
| 잘못된 저장값(항목) — `a:null,cash:'abc'` · 체결에 null/숫자/날짜 없는 항목 | 동일 | 패널 0행 + 스크립트 오류 | 체결 3건 격리(원본 `_bad` 보관) · 유효 1건 유지·재저장 · cash 0 · 배너에 「일부(3건)」 |
| 이전 버전 저장값 — `b_view_v1`(v113 폐기) · `qqq_signal_strat='A'` · `scen='us_1972'` · 옛 접힘 형식 · dq 없는 체결 | 동일 | 전부 정상(폐기 키 삭제 · 보정 · 호환) | 확인만 |
| **중간 저장 실패 — 복원 직전 되돌리기 스냅샷**(`b_undo_v1` 만 QuotaExceeded) | `setItem` 대역 + `applyBackup` | **그대로 덮어쓰고 true 반환 · 「복원했습니다 · 되돌리기」 칩 표시 · 되돌릴 스냅샷 없음**(칩을 누르면 「되돌릴 이전 상태가 없습니다」) — 원래 값이 훼손된 채 정상 완료처럼 보임 | **복원 중단 + 알림**(「복원 전 상태를 보관하지 못해 중단 — 아무것도 바꾸지 않았습니다」) · PORT·저장값 불변 · 칩 없음 |
| 복원 파일의 일부 항목이 형식 불량 | 체결 3건 중 2건 불량 | 조용히 버리고 「체결 1건으로 덮어씁니다」만 | 확인창에 「형식이 맞지 않는 체결 2건은 제외됩니다」 병기(살균 규칙 v186 그대로) |
| 정상 복원 | 스냅샷 저장 성공 | 정상 | 정상(되돌리기 칩·스냅샷 존재) |

수정: `lsSet` 성공 여부 반환 · `loadPort`/`loadTrades`/`load()` 가 `sanitizeBackup` 과 같은 문을 지나고 손상값은 `quarantine()` · `applyBackup` 스냅샷 실패 시 중단 · `sanitizeBackup.dropped`(비열거 · 백업 파일에 안 섞임). 회귀 D2~D4.
