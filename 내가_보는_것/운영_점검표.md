# 운영 점검표 — 내가 언제 뭘 해야 하나

> 이 문서 하나만 보면 된다. 파일 경로를 외울 필요 없다.
> 작성 2026-08-31 · v140 개정(자동 파수꾼 도입으로 정기 파이썬 실행 의무 삭제).

---

## ★ 원칙 — 화면만으로 충분하다

**내가 알아야 할 정보와 내가 눌러야 할 기능은 전부 웹 화면(오늘의 신호 · 설명서) 안에 있다.**
파일을 열어야만 알 수 있는 운영 정보는 만들지 않는다. 새 점검거리가 생기면
**자동으로 돌리고 결과만 화면에 띄운다** — 이건 AI 규약(CLAUDE.md §3)에 못 박혀 있다.

그래서 이 폴더의 문서들은 **참고용**이다. 평소에는 안 읽어도 된다.

---

## 결론부터 — 내가 직접 하는 일은 2가지뿐이다

둘 다 **주식을 실제로 사고파는 일**이다. 그 밖에는 아무것도 없다.

| 언제 | 무엇을 | 얼마나 걸리나 |
|---|---|---|
| **연 2~3회** (카톡이 옴) | 전환일 주문 — 09:05~15:20 | 10분 |
| **방어 중 30일마다** (**카톡이 옴** · v140) | 방어 비율 40/40/20 맞추기 | 5분 |

**둘 다 카톡이 먼저 온다.** 달력을 볼 필요도, 앱을 매일 열어볼 필요도 없다 —
알림이 오면 그때 화면을 열면 된다.

둘 다 **몇 주를 사고팔지 화면이 계산해 준다** (내 포트폴리오 패널의 「오늘의 행동」 →
주문 메모 복사). 나는 그대로 주문만 넣으면 된다.

> **정기적으로 파이썬을 돌릴 의무는 없다.** 예전의 「분기 1회 점검」은
> 자동 파수꾼이 매주 대신 돌린다 (아래 §1).

## 1. 자동 — 아무것도 안 해도 된다

| 무엇 | 언제 | 문제가 생기면 |
|---|---|---|
| 신호 갱신 (미국 종가 → 판정) | **매일 새벽** | 실패 시 **카톡** |
| 성과표·지평표 데이터 최신화 | **매월 1일** | 검증 통과 시에만 반영 |
| 화면 배포 | 코드가 바뀔 때 | — |
| 검증 게이트 (I1~I14) | 매 변경 + 정기 | 실패 시 이슈·메일 알림 — 화면 배포와는 독립 |
| **신호가 멈췄는지 감시** (v140) | **매 평일 08:40** | 3영업일 밀리면 **카톡** |
| **방어 재조정일 알림** (v140) | **방어 중 30일마다** | 그날 아침 **카톡** |
| **전환 실행일 재알림** (v192) | **전환 실행일 08:40** | 새벽 알림을 못 봤을 때의 두 번째 **카톡** |
| **근접 진입 알림** (v192) | **게이지가 「근접」에 들어선 날 08:40** | **카톡** — 아직 할 일 없음 · 그 주 자리 비우지 말 것 |
| **알림 채널이 살아 있는지 확인** (v140) | **매 평일** | 카톡이 죽어 있으면 **다른 경로로** 알림 |
| **전제·상품·비용 점검** (v140) | **매주 월요일** | 나빠졌을 때만 **카톡 + 화면 배너** |
| **휴장일 표 연장** (v195) | **매주 월요일** (실제로 바뀌는 건 매년 1월) | — 자동. 임시공휴일만 사람이 |

> 이건 GitHub Actions 가 돈다. 컴퓨터를 안 켜도 굴러간다.

### 왜 「감시」가 따로 필요한가

기존 알림은 **작업이 돌다가 실패했을 때**만 왔다. 그런데 실제로 위험한 건 반대다 —
**아예 안 도는 것**은 실패가 아니라서 알림이 안 온다. 화면을 며칠 안 열면 모른다.
큰 하락 초입의 방어 전환을 놓치면 최악 −96.5% 다. 그래서 v140 에서
「아무 일도 안 일어난 것」을 감시하는 파수꾼을 따로 세웠다.

같은 이유로 **알림 채널 자체의 생존**도 매일 확인한다. 카카오 토큰은 시한부라
그냥 두면 정작 전환일에 조용히 죽어 있을 수 있었다.

## 3. 자동 점검이 보는 것 — 화면에 뜬 말의 뜻

평소엔 「자동 점검 · 이상 없음」 한 줄뿐이다. 배너가 뜨면 그 안의 문장을
**AI에게 그대로 복사해 주면 된다.** 아래는 그 문장을 이해하고 싶을 때만.

**[1] 전제 감시** — 전략이 서 있는 땅이 흔들리는지 본다.

이 전략은 **「지수가 길게 오른다」 + 「2배가 제대로 굴러간다」** 두 전제 위에 서 있다.
그 둘을 각각 두 개씩, 총 **느린 변수 4개**로 본다.

| 무엇을 재나 | 어느 전제 | 주의선 | 역사 범위 밖 | 나빠지는 방향 |
|---|---|---:|---:|---|
| 지수 **10년 수익률** (나스닥100 연평균) | 지수가 오르나 | +4.1% | −8.1% | 낮아지면 |
| 지수 **20년 수익률** | 지수가 오르나 | +9.5% | +3.1% | 낮아지면 |
| 지수 **3년 변동성** (연율 출렁임) | 2배가 굴러가나 | 35.6% | 51.9% | 높아지면 |
| **2배 드래그** (2배가 지수 2배에서 뒤처지는 폭) | 2배가 굴러가나 | 11.7%/yr | 29.4%/yr | 높아지면 |

- **왜 「느린」인가**: 창이 10년·20년·3년이라 하루하루 안 움직인다. 매일 볼 필요가 없다.
- **예측이 아니다**: 이미 일어난 것을 잰다. 선행 경보는 검증 결과 존재하지 않는다(04 §5-6).
- **밴드는 임의값이 아니다**: 주의선 = 54년 분포의 **하위/상위 10%**, 역사 범위 밖 =
  **54년 최저/최고**. 「본 것 중 가장 나쁜 10%」와 「본 적 없음」이다.
  (20년 수익률 3.1% 는 배포 게이트 I10 P2 가 자동 검사하는 3% 와 같은 선)
- **★ 4개가 동등하지 않다**: 변동성·드래그는 *성적*을 바꾸지만 **수익률(드리프트)은
  레버리지를 쓸지 말지 자체를 뒤집는다.** 일본 1989 검증 — 규칙은 이겼는데(B×2배 0.31배
  vs 2배 맨몸 0.15배) **1배 지수가 1.70배**였다. 규칙이 이겨도 레버리지가 손해인 상황이
  있다. **수익률이 걸린 Level 2 는 다른 변수가 걸린 것과 같은 무게로 읽지 말 것.**

이 4개가 역사 분포 어디쯤인지 확인해 **Level 0~3** 로 판정한다.
**어떤 경우에도 자동으로 전략이 바뀌지 않는다** — 대응은 전부 「연구를 시작한다」까지다.

| 판정 | 뜻 | 할 일 |
|---|---|---|
| **Level 0** | 정상 | 없음 |
| **Level 1** | 1개 변수가 주의선 밖 | 없음 — 파수꾼이 계속 본다 |
| **Level 2** | 2개 이상 밖 | **AI에게 재검토 연구를 시킨다** (전략 변경 아님) |
| **Level 3** | 역사 범위 밖 | **AI에게 유지 여부 재검증을 시킨다** |

**[2] 상품 생존** — 4다리 ETF 가 아직 살아 있나(시가총액). 상장폐지되면 전환 자체를
못 하므로 미리 본다. 경보가 뜨면 대체 상품으로 갈아탄다.

**[3] 체결 비용** — 백테스트가 쓰는 0.2% 비용 가정이 실제와 맞나. 전환 신호가 떴다는 사실만으로는
실제 체결가를 알 수 없다. 화면에서 저장한 백업을 `점검.py --exec-backup 백업.json`으로 넘겨 **같은 날짜·같은 종목 NAV와 맞는 실제 체결일 20일**이
쌓여야 판정한다. 백업이 없으면 진행률은 0/20이며, 자동 점검의 일별 NAV 괴리는 자료 수집 상태만 감시한다.

> **이 점검은 전략을 바꾸지 않는다.** 이상이 나와도 기본 대응은 「지켜본다」다.
> 선행 예측형 경보는 검증 결과 존재하지 않으므로(04 §5-6) 수준 감시만 한다.

### 직접 돌려보고 싶으면 (선택 — 안 해도 된다)

```bash
python 내가_보는_것/점검.py
```

저장소 폴더에서 이 한 줄. 화면에 뜬 것과 **같은 계산**이 한국어로 자세히 나온다.

## 4. 전환일에 할 일 (카톡이 오는 날, 연 2~3회)

1. 화면에서 **오늘 전환 신호**와 무엇을 사고 팔지 확인
2. 내 포트폴리오의 **「오늘의 행동」**이 계산해 준 수량대로 (주문 메모 복사 버튼)
3. 한국장 **09:05~15:20** 에 전량 전환
4. **체결가 기록** (보유가 자동 반영됨)

주문 방법(괴리율·지정가·호가창)을 모르겠으면 화면의 **설명서 §③** 에 다 있다.

### ★ 모든 전환이 똑같이 중요하지는 않다

실측 결과 **전환을 하루 놓쳐도 139번 중 102번은 오히려 이득**이었다(중앙 +1.9%).
**단 하나 예외** — 큰 하락의 초입에서의 방어 전환은 놓치면 치명적이다
(2000년 닷컴 진입을 놓쳤다면 최종 **−96.5%**).

> **실전 규칙**: 낙폭 게이지가 **「근접」**이면 무슨 일이 있어도 그날 체결.
> **「여유」**면 하루 이틀 늦어도 괜찮다.

### 흔들릴 때 보는 숫자

전환의 **54%는 하고 나서 손해**를 본다. 최장 **10번 연속** 틀린 적도 있고 그때 누적
−20.4% 였다. **이게 정상 범위다** — 수익은 드문 큰 약세장 한두 번에서 나오고 나머지는
조금씩 지는 구조라서다.

## 5. 이 폴더가 뭐가 뭔지 (헷갈릴 때만)

내 것은 **세 종류**뿐이다 — ① 웹 화면 3개, ② `내가_보는_것/` 폴더, ③ 화면이 저장해 주는 파일.

### ① 웹 화면 — 폰·PC 브라우저로 연다 (파일로 열지 않는다)

**여기에 필요한 게 전부 있다.** 화면 맨 위에 탭 세 개가 있고, 그게 전부다.

| 탭 | 주소 | 무엇 |
|---|---|---|
| **오늘의 신호** | `scarzsearch-cyber.github.io/nasdaq-signal/` | 오늘 할 일·포트폴리오·계산기·자동 점검 |
| **설명서** | 위 화면에서 「설명서」 탭 | 전략 이해·주문 방법·FAQ |
| **업데이트 노트** | 위 화면에서 「업데이트 노트」 탭 | 무엇이 바뀌었나 · 규칙 변경 0회 기록 (v142) |

> 이 셋의 파일 이름은 `signal.html`·`guide.html`·`notes.html` 이지만 **그 이름을 쓸 일이 없다.**
> 홈 화면에 추가해 두면 앱처럼 열린다.

### ② `내가_보는_것/` 폴더 — 참고용 (평소엔 안 열어도 된다)

| | |
|---|---|
| **`운영_점검표.md`** | **이 문서** — 내가 언제 뭘 하나 |

| `전략_요약.md` | 전략 한 장 요약 + AI 문서 지도 |

### ③ 화면이 저장해 주는 파일 — 다운로드 폴더에 떨어진다

| | |
|---|---|
| `나스닥신호_백업_날짜.json` | 백업 (카톡으로 보내는 것도 이것) |

### 그 밖 — 전부 AI 작업용, 열어볼 일 없음

`01`~`04_*.md` · `CLAUDE.md` · `HANDOFF.md` · `FILES.md` (AI 규칙·기록) ·

> (AI 규약에 등록됨). 그런데 규약은 그보다 먼저 **자동화부터 시도**하게 되어 있다.

## 6. 이상이 생겼을 때 AI에게 시킬 말

복사해서 그대로 쓰면 된다.

**화면에 자동 점검 배너가 떴을 때**
```
화면에 자동 점검 배너가 떴어. 확인하고 필요한 조치를 해줘.
(배너 문장 붙여넣기)
```

**카톡으로 알림이 왔을 때 (신호 실패 · 신호 멈춤 · 알림 채널 이상)**
```
카톡으로 (내용) 알림이 왔어. 원인 확인하고 조치해줘.
```

**화면이 이상할 때**
```
화면에서 (무엇이) 이상해. 확인해줘.
```
