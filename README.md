# 나스닥 레버리지 전환 전략

QQQ 의 252일 낙폭으로 **2배 레버리지**와 **방어 바스켓**을 오가는 전략.
신호는 매일 자동으로 갱신되고 화면에 뜬다 → **https://scarzsearch-cyber.github.io/nasdaq-signal/**

---

## 1. 전략 (이게 전부다)

| | |
|---|---|
| **신호** | QQQ **미국 종가**의 252일 낙폭 |
| **진입** | 낙폭 ≤ **−16%** → 방어로 전량 전환 |
| **복귀** | 낙폭 > **−16%**(규칙 B, 기본) 또는 **−11%**(규칙 A) → 레버리지로 전량 복귀 |
| **공격** | TIGER 미국나스닥100레버리지(합성) `418660` |
| **방어** | 배당40 `458730` / 미국채40 `305080` / 금20 `411060` — **비중 고정**, 월 1회 재조정 |
| **체결** | 전일 미국 종가 신호 → 다음 한국 거래일. 09:05~15:20 사이 아무 때나 |

전부 시험했고 전부 기각됐다(`docs/` 참조).

## 2. 자동화 — 사용자가 할 일은 없다

```
매 평일 22:30 / 23:30 / 00:30 UTC   daily-signal.yml
   └ deploy/update_signal.py   QQQ 종가 → data/signal.json
   └ deploy/nav_collect.py     국내 ETF 실측 NAV 한 줄 적립
        ↓ (성공하면)
   pages.yml                   화면 재배포
        ↓
매 평일 01:00 UTC               verify.yml  ← [v37 신설]
   └ verify_all.py             불변식 12종 검사. 실패하면 **이슈 자동 생성**
   └ audit_full.py             59개 파일 전수조사 + 시점별 재계산
```

**예약 슬롯이 3개인 이유**: GitHub 은 부하가 걸리면 예약 실행을 **통째로 버린다**
(2026-08-26 에 실제로 발생, 종가가 하루 밀렸다). 한 번 놓쳐도 한국장 개장 전에 따라잡는다.

**그래도 밀리면**: 화면 맨 위에 **경고 배너**가 뜬다(3거래일 주의 / 5거래일 이상 빨간 경고).
배너의 링크를 눌러 Actions → 「일일 신호 갱신」 → Run workflow 하면 즉시 갱신된다.

### 수동으로 해야 하는 것 (모형을 바꿨을 때만)

## 5. 왜 오류가 났는가 — 2026-08-27 의 12건 분석

하루에 12건을 찾았다. 무작위가 아니라 **구조적 패턴**이 있었다.

| 원인 | 건수 | 무엇 |
|---|---:|---|
| **① 검산 함수가 없던 곳** | **2** | `mix_monthly_parts`(비용 분모) · `accumulate`(2일 지연) |
| ② 엔진을 안 쓰고 새로 짬 | 2 | `axis_macro.bt()` 직접 구현 · 검증 하네스가 `verify.py` 구성 미재현 |
| ③ 모형이 실제 상품과 다름 | 1 | 「미국채10년**선물**」을 현물로 모형화 |
| ④ 검증 설계 오류 | 5 | 격자 단면만 봄 · 수익 기준 워크포워드 · MDD 초기허수 · 최악값 인용 · 하드코딩 판정문 |
| ⑤ 의존성 추적 실패 | 1 | 공용 모형 변경 후 사용처 6개 미재실행 |
| ⑥ 플랫폼 | 1 | GitHub 예약 실행 누락 |

### 가장 중요한 발견

> **검산 함수가 있던 코드는 12건 중 0건이 틀렸다.**
> `run` / `sim` / `sim_hold` / `after_tax` 는 `check()` 가 매번 대조했고 전부 정확했다.
> `accumulate` / `mix_monthly` 는 검산이 없었고 **둘 다 틀렸다.**

**파일이 많아서 못 찾은 게 아니다.** ⑤ 한 건만 파일 수와 관련 있고,
그것도 `grep -rl` 로 즉시 해결됐다. 진짜 원인은 **불변식을 코드로 못박지 않은 것**이다.

## 6. 새 분석을 할 때 — `research_kit.py` 를 써라

「검증 설계 오류」는 린터로 사후 탐지할 수 없다. 대신 **틀린 방법을 어렵게** 만들었다.

```python
from research_kit import sweep, walkforward, mdd, mdd_vs_paid, dist, verdict
```

| 함수 | 무엇을 막는가 | 어떻게 |
|---|---|---|
| `sweep()` | 격자 단면만 보고 '첨탑' 오판 | 전 차원을 훑고 **최적점이 경계면 예외를 던진다**. 고원 여부도 판정 |
| `walkforward()` | 수익 기준 선택으로 잡음 고르기 | 지표를 필수 인자로 받고 **`fixed=` 고정 대조군 없이는 거부** |
| `mdd()` | 적립 초기 잔고를 낙폭으로 셈 | `kind='accum'` 이면 **`since=` 없이는 거부** |
| `mdd_vs_paid()` | — | 원금 대비 최악. 적립식에서 가장 체감되는 수치 |
| `dist()` | 분포에서 한 숫자만 뽑아 인용 | 중앙·5분위·최악을 **항상 함께** 반환. 표본 3개 미만이면 거부 |
| `verdict()` | 계산과 무관한 판정문 | 관문 결과에서 문장을 **생성**한다 |

`python research_kit.py` 가 실제로 났던 오류를 재현해 막히는지 검사한다(CI 가 부른다).

### 그래도 사람이 봐야 하는 것

- [ ] **엔진을 재구현하지 말 것.** `axis_lib.sim` / `sim_def` / `sim_hold` 를 써라.
      새로 짜야 한다면 기존 엔진과 오차 0 인지 먼저 검산하라.
- [ ] **격자는 전 방향으로 넓혀 볼 것.** 최적점이 경계에 붙어 있으면 격자 밖까지 늘려라.
      v31 이 단면 하나만 보고 "첨탑"이라 오판했다.
- [ ] **워크포워드는 Calmar 로 고를 것.** 수익으로 고르면 잡음을 고른다.
      **더 나은 건 아예 안 고르고 못박는 것**이다(v32: 고정 8/9 vs 선택 5/9).
- [ ] **적립식 MDD 는 납입 종료 후 또는 원금 대비로 잴 것.** 초기 잔고가 1단위일 때의
      등락이 낙폭으로 잡힌다(−23% 가 −70% 로 부풀었다).
- [ ] **중앙값과 최악값을 구분해 인용할 것.**
- [ ] **판정문에 숫자를 하드코딩하지 말 것.** 계산 결과에서 만들어라.
      `audit_full.py` 의 스캐너도 서술형 문장은 못 잡는다.
- [ ] **달러와 원화가 갈리면 원화가 기준.** 실제로 사는 게 원화 상품이다.
- [ ] **전구간 배수를 믿지 말 것.** 데이터 출처별로 쪼개라
      (1972-1985 나스닥종합 합성 / 1985-1999 NDX / 1999- QQQ 실물).
- [ ] **한국 ETF 는 일간 상관으로 검증하지 말 것.** 세션 시차 때문에 낮게 나온다.
      주간/월간 또는 shift+1 로 봐라.
- [ ] **`pct_change` 는 교집합 후에 계산할 것.** 먼저 하면 드리프트가 부풀려진다.
- [ ] **상대 변화율을 절대 순위로 읽지 말 것.** "A 가 덜 깎인다" ≠ "A 가 낫다".
      v21 이 이걸로 21년 묵은 잘못된 권고를 남겼다(v43).
- [ ] **표준편차를 평균비용과 직접 비교하지 말 것.** 방향 없는 분산의 비용은 **σ²/2**.
      2.58% 표준편차는 회당 0.033% 이지 2.58% 가 아니다(v43).
- [ ] **문서에서 결정했으면 화면도 고칠 것.** v43 이 "A 는 선택지가 아니다"라고
      결정했는데 `signal.html` 은 두 달 뒤까지 A 를 고를 수 있게 두고 있었다(v45).
      이제 `verify_all.py` I5 가 화면을 직접 읽어 대조한다.
- [ ] **부분 지표만 나란히 보여주지 말 것.** 선택 카드가 MDD·Calmar·Sortino 만
      보여줘서 실물 TIGER 탭에서 A 가 3개 다 이기는 것처럼 보였다. 최종배수가
      빠져 있었다(v45). 이건 v21 이 A 를 잘못 권한 것과 같은 구조다.
- [ ] **사본을 만들었으면 원본과 대조할 것.** `signal.json` 이 `strategy_stats.json`
      의 사본을 들고 있었고, v36 정정 뒤 화면이 옛 수치(263,062배)를 보여줬다(v45).
      I6 이 이제 매번 대조한다.
- [ ] **관문을 다 통과해도 집중도를 볼 것.** v53 은 중앙·P20·P5·MDD·4블록·
      파라미터능선·비용·시작일까지 **10관문을 전부 통과**하고도, 상위 3개 사건을
      빼니 P5 가 −4% 로 뒤집혔다(독립 위기 9개, 최소 19 미달).
      `research_kit.concentration()` 과 `leave_one_crisis_out()` 을 반드시 쓸 것.
- [ ] **최종 후보는 미니맥스로 확인할 것.** 과적합의 지문은 "고른 표본에서 1등,
      나머지에서 붕괴"다. 겹치지 않는 구간별 순위를 매겨 **최악 순위**를 봐라.
      현행은 6구간 최악 126위(미니맥스 3위/210)인데 각 구간 1등들은 146~207위다(v56).
      `research/axis_minimax.py` 참고.
- [ ] **`or dd > 진입선` 형태를 조심할 것.** 그 분기는 이미 `dd > 진입선` 일 때만
      도달하므로 조건이 **항상 참**이 되어 무발동이다. v50·v52·v55·v59 초판에서
      **네 번** 같은 실수를 했다. 추가 조건은 `or` 가 아니라 `and` 로 걸어라.
- [ ] **기준선과 수치가 똑같이 나오면 '좋은 결과'가 아니라 '무발동'이다.**
      `DD > −16% **또는** 조건` 형태는 DD 가 먼저 참이 되어 조건이 구속력을
      갖지 못한다. v50·v52·v55 초판에서 세 번 같은 실수를 했다.
      후보 표에 중앙값·회전량이 기준선과 일치하면 **무발동**으로 표시할 것.

### 남는 위험과, 사용자가 쓸 수 있는 지렛대

위 도구로도 **완전히는 못 막는다.** 정직하게 적는다.

`research_kit` 은 **내가 그 함수를 쓸 때만** 작동한다. 급해서 직접 짜면 무력하다.
그리고 "이 축을 아예 안 봤다" 같은 누락은 어떤 도구로도 못 잡는다.

**그런데 2026-08-27 에 12건을 실제로 찾아낸 건 도구가 아니라 사용자의 되묻기였다.**

| 사용자가 한 말 | 그래서 나온 것 |
|---|---|
| "이게 폴더 내 모든 걸 훑은 거야?" | 라이브 파이프라인 4개를 안 봤다는 사실 |
| "모든 걸 다 검증한 거 맞지?" | 모형 바꾸고 하위 6개 미재실행 → v27 근거 뒤집힘 |
| "완벽한 거지?" | 적립 2일 지연 (프로젝트 코드 4곳) |
| "국채 롤비용 계산해봐" | 현물/선물 혼동 — 54년 내내 과대계상 |

**가장 효과적인 4가지 되묻기** — 설계 오류 5종에 정확히 대응한다:

1. **"그 숫자 중앙값이야 최악값이야?"** → 통계 바꿔치기를 잡는다
2. **"어느 구간에서 나온 이득이야?"** → 1970년대 금, 고금리 국채 같은 편중을 잡는다
3. **"안 하면 어떻게 되는데?"** → 대조군 없는 주장을 잡는다
4. **"그 문장 계산에서 나온 거야, 네가 쓴 거야?"** → 하드코딩 판정문을 잡는다

**결론: 도구가 4/5 를 막고, 나머지는 되물어야 나온다.**
"내가 알아서 다 보겠다"는 답은 오늘 12번 틀렸으므로 하지 않는다.

## 6-2. 이 전략은 나스닥 전용이다 (v44)

같은 규칙을 다른 지수에 그대로 적용해봤다.

| 시장 | 전략 | 그냥 보유 | 2배 보유 MDD |
|---|---:|---:|---:|
| 나스닥100 | **14,529** | 1,921 | −98.7% |
| 나스닥종합 | **45,063** | 2,321 | −97.8% |
| **S&P500** | **69.3** | **161.7** | −85.7% |
| **코스피** | **4.4** | **5.9** | −90.6% |

**S&P500·코스피에서는 그냥 보유에 진다.** 최적 진입선도 다르다
(S&P500 −19%, 코스피 −13%/−23%).

전략의 값어치는 **레버리지가 재앙적으로 무너지는 걸 막는 것**이다.
S&P500 은 −86% 로 덜 극단적이고, 코스피는 29년간 2배로 4.4배라 지킬 상승이 없다.

> **함의 두 가지**
> ① 다른 시장 데이터로 표본을 늘릴 수 없다 — 규칙이 시장마다 다르다
> ② **나스닥의 성질이 변하면 우위도 사라진다** → `verify_all.py` **I10** 이 감시한다
