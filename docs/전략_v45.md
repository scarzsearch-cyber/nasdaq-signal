# 전략 v45 — 문서가 결정한 것을 화면이 따르지 않았다

작성 2026-08-27. 대상 `signal.html`, `deploy/build_stats.py`, `verify_all.py`.

## 0. 답

> **사용자 질문: "보조전략이 쓸데 없다면 왜 웹에 −16/−11 선택지가 있는거야?"**
>
> **맞는 지적이다. 남아 있으면 안 되는 것이었다.**
> v43 §4 가 "A 는 선택지가 아니라 참조"라고 **결정했는데 코드는 안 바꿨다.**
> 태그만 `기존` → `참조` 로 고치고 **버튼은 그대로 뒀다.**
>
> 그리고 그 김에 확인하다 **라이브 버그를 하나 더 찾았다.**
> 화면이 v36 정정 **이전** 수치를 보여주고 있었다 (54년 263,062배 vs 실제 214,076배).

---

## 1. A 가 선택지로 남아 있던 문제

### 1-1. 태그만 바꾸고 동작은 안 바꿨다

v43 §4:

> **보조전략은 두지 않는다.** … A 는 참조용으로만 화면에 남긴다.
> 다만 **선택지가 아니라 참조임을 분명히 한다.**

그런데 `signal.html` 은 A 를 **B 와 똑같은 크기의 버튼**으로 그리고 있었고,
누르면 `sel = 'A'` 가 되어 **"오늘 뭘 사야 하나"가 통째로 바뀌었다.**
게다가 `localStorage` 에 저장돼 **한 번 잘못 누르면 계속 A 로 남았다.**

### 1-2. 화면이 A 를 더 좋아 보이게 만들고 있었다

선택 카드는 **MDD · CALMAR · SORTINO 세 개만** 보여줬다. **최종배수는 없었다.**

| 시나리오 | 최종배수 | MDD | Calmar | Sortino |
|---|---:|---:|---:|---:|
| 원화 · 실물 TIGER | B 2.9 / **A 3.1** | B −44.9 / **A −37.0** | B 0.868 / **A 1.141** | B 1.488 / **A 1.609** |

**실물 TIGER 탭에서 A 가 보이는 지표 3개를 전부 이겼고, 전부 초록색이었다.**
가장 "실제처럼" 보이는 탭에서 화면이 A 를 권하고 있던 셈이다.

이건 v21 이 A 를 잘못 권했던 것과 **같은 구조의 오류**다 — 부분 지표만 보고 순위를 읽는 것.

### 1-3. 고친 것

| | 전 | 후 |
|---|---|---|
| A 의 DOM | `<button>` | `<div class="opt ref">` (점선·흐림·커서 없음) |
| 클릭 핸들러 | `.opt` 전부 | **`button.opt` 만** |
| 저장된 `sel='A'` | 그대로 유지 | **B 로 되돌리고 키 삭제** |
| `signal.json` 의 `default` | 그대로 채택 | **참조 규칙이면 무시** |
| 카드 지표 | MDD·Calmar·Sortino | **최종배수** + 3개 |
| 제목 | "전략 선택" | **"규칙"** |
| 얇은 표본 | 표시 없음 | **전환 19회 미만이면 경고** |

마지막 항목이 §1-2 의 재발을 막는다. 실물 TIGER 구간은 전환이 **B 6회 / A 2회**뿐이라
v41 이 정한 최소 표본(독립 위기 19회)에 한참 못 미친다. 이제 화면이 그렇게 적는다.

## 2. 덤으로 찾은 라이브 버그 — 화면이 v36 이전 수치를 보여주고 있었다

### 2-1. 무슨 일이

`signal.html` 은 성과지표를 이렇게 읽는다:

```js
if(AUTO && AUTO.stats) STATS = AUTO.stats;                  // signal.json 안의 사본 (우선)
if(!STATS){ STATS = await getJSON('data/strategy_stats.json'); }   // 원본 (뒷순위)
```

**`signal.json` 이 `strategy_stats.json` 의 사본을 안에 들고 있고, 화면은 사본을 우선한다.**

| | 판 | 54년 B |
|---|---|---:|
| `signal.json` 내장 사본 | 2026-08-26 16:57 UTC | **263,062배** ← 화면에 뜨던 값 |
| `strategy_stats.json` 원본 | 2026-08-27 01:37 UTC | **214,076배** ← 맞는 값 |

**23% 과대 표시.** v36(국채를 선물형으로 정정)의 효과가 화면에 반영되지 않았다.

### 2-2. 왜

```
08-27 00:30 UTC   일일 봇 실행 → signal.json 생성 (그때의 stats 사본을 박음)
08-27 01:37 UTC   내가 build_stats.py 재실행 → strategy_stats.json 만 갱신
                  → signal.json 안의 사본은 옛 판 그대로
```

`build_stats.py` 는 원본만 쓰고 **사본은 안 건드렸다.** 다음 일일 실행까지 어긋난 채로 간다.
**공용 모형을 바꾸면 사용처를 전부 재실행해야 한다**는 v36 의 교훈이, 라이브 쪽에는 적용돼 있지 않았다.

### 2-3. 고친 것

1. `deploy/update_signal.py` 재실행 → 사본을 현재 판으로 갱신 (**즉시 해소**)
2. `deploy/build_stats.py` 가 원본을 쓰면 **`signal.json` 안의 사본도 같이 갱신**
3. `verify_all.py` **I6** 에 검사 추가 — 사본과 원본의 `generated_at` 및 8개 최종배수 대조
4. `deploy/update_signal.py` 의 stdout 을 UTF-8 로 — 윈도우에서 마지막 print 가 죽어
   수동 실행이 실패처럼 보였다

**검사가 실제로 잡는지 확인했다.** 일부러 옛 판으로 되돌리니:

```
[FAIL] signal.json 내장 stats 가 strategy_stats.json 과 같은 판
       내장 2026-08-26 16:57 UTC vs 원본 2026-08-27 01:37 UTC
[FAIL] 내장 us_1972 B 최종배수 일치   263,062.5 vs 214,076.1
```

## 3. 근본 원인 — 문서와 화면을 아무도 대조하지 않았다

`verify_all.py` 는 **엔진·데이터·문서**를 검사했지만 **`signal.html` 은 한 번도 안 읽었다.**
그래서 "문서는 결정했는데 화면은 안 따랐다"가 **아무 검사에도 안 걸렸다.**

### I5 에 화면 검사 5종 추가

| 검사 | 막는 것 |
|---|---|
| A 가 `ref:true` 로 표시된다 | 참조가 다시 선택지가 되는 것 |
| 클릭 선택자가 `button.opt` 다 | 참조 카드에 핸들러가 붙는 것 |
| 기본 규칙이 B 다 | 기본값 표류 |
| 저장된 참조 선택을 되돌린다 | 옛 사용자가 A 에 갇히는 것 |
| 최종배수를 함께 보여준다 | §1-2 의 부분 지표 착시 |

**이번 것과 똑같은 계열의 오류다** — v37 이 정리한 원인 그대로:
**검산 함수가 있던 코드는 12건 중 0건이 틀렸다.** 화면에는 검산이 없었다.
