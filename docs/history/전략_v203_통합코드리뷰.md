> **[v210 정정 2026-09-05]** 이 문서의 ISA 20년 수치(연장 135.24 · 3년 해지 114.38 · 일반 87.44 ·
> 세전 149.99배 · +54.7%)와 54년 B 217,110배는 FRED 빈 가격 행 제거(v210) 전 값이다 —

## 1. 결론

이번 리뷰가 바꾼 것은 전략이 아니라 **틀린 측정과 조용한 실패**다.

- 현행 전략 B 성과 지문은 `us_2000 167.315` · `us_1972 217110.075` ·
  `kr_1997 2799.948` · `kr_real 2.863`으로 불변이다.
- 세금·사건 수·표본 창·플라시보처럼 잘못 세었던 연구 수치는 다시 계산해 현행 문서와
  화면에 반영했다. 그 결과도 전략 B 유지이며, 기각 후보를 되살릴 근거는 없었다.
- 배포 코드는 빈 자료·잘못된 API 응답·토큰 교체 실패를 성공으로 숨기지 않고 실패로
  드러내게 했다. 화면 배포와 검증은 서로 독립인 fail-open 구조를 유지한다.

## 2. 공용 계산 엔진

### 세금·적립 회계

- 전환일은 **기존 자산 매도와 세금 정산 뒤 새 자산의 그날 수익**을 적용한다.
- 연말 세금을 계좌에서 꺼내는 일부 매도는 평가액뿐 아니라 대응 취득원가도 줄이고,
  그 매도가 만든 2차 실현손익을 다음 연도 손익에 넘긴다.
- 만기 1회 과세는 분수 비중을 선형 혼합한다. 자산별 원가를 추적하지 않는 중간실현·
  연간과세·적립 모형은 분수 비중을 몰래 0/1로 바꾸지 않고 명시적으로 거부한다.
- 적립 경로의 원금 대비 하락을 재기 위해 평가액과 누적납입 경로를 선택적으로 반환한다.

손계산 가능한 장난감 경로와 세율 0 축퇴를 `axis_lib.check()`에 넣어 같은 엔진이 자기
결과만 되풀이하지 않게 했다. 해외 직투 연간과세 최종배수는 다음처럼 내려갔다.

|---|---:|---:|---:|---:|
| 2000~ | 68.60배 | 116.22배 | 164.86배 | 194.57배 |

### 비교·표본·인과

- `axis_macro4.py`는 기준선과 짝이 없는 21개를 승리로 세던 오류를 고쳤다. MDD 관문은
  42/42지만 수익 개선은 **30/42**, 고정 기준선 비교는 **비교 가능한 21/21**이고
  나머지 21개는 비교 불가다.
- `axis_macro2.py`·`axis_macro3.py`의 워크포워드 선택은 최종금액이 아니라 등록한
  Calmar 목적함수로 고쳤다. 현재 자료에서는 선택 후보가 우연히 같아 결과값은 불변이다.
- 이 세 매크로 보관 연구표의 252거래일 연율과 공표 엔진의 실제 달력연수를 전 격자로
  교차 계산했다. 선택은 모두 같았으며, 코드에는 두 규약을 혼동하지 않도록 명시했다.
- `axis_meta_crisis.py`는 아직 끝나지 않은 미래 위기창을 완성 사건으로 세지 않는다.
  현재 완성 사건은 **1/3**이다.
- `axis_t4_shadow.py`의 v68 재현 관문은 늘어나는 현재 데이터와 고정된 과거 숫자를
  비교하지 않고, v68 입력 종료일 2026-08-26까지 같은 창으로 잘라 판정한다. 사건은
  모든 원시 도피 시작점을 기준으로 간격을 묶어 **21회**로 바로잡고 공식 M1(0.7)을 먼저 표시한다.
- `axis_krspread.py`는 고정 종료일 대신 실제 관측 종료일을 쓰고, 여러 변수를 함께 바꾼
  표에서 한 변수만 원인이라고 단정하던 문장을 내렸다.
- `def_equity.py`는 신호의 하루 시차와 진짜 경로 MDD를 반영했다. 후보의 P5/P20 개선은
  각각 `+4.8%`·`+5.8%`(배수의 상대 개선)지만 배당 −40%·국채 +10%·금 +30%를
  함께 바꾼 비교라 원인을 특정할 수 없다. 현행의 무작위 배합 위치는 같은 창 기준
  원화 43·달러 40백분위이고, 1972~ 달러는 66백분위다.
- `axis_dca.py`는 RSI 경계, 이동평균 워밍업, 분수 납입, 전환일 체결가를 바로잡았다.
  가장 나은 후보도 현행 대비 중앙 −22%·승률 49%라 전 후보 기각은 유지된다.
- `reentry_lib.py`는 방어 중 추가 하락 때마다 쿨다운 시계를 되감던 오류를 고쳤다.
  기준선 142.3배, CD(10) 186.8배, CD(13) 189.6배로 움직였지만 표본 밖 톱니 위험에
  따른 기각은 유지된다.
- `axis_macro3.py`의 변화량 시차표는 동시 2개·후행 1개·선행 0개이며 비동시 최대
  절대상관은 0.095다. “하루 시차면 0”이라는 과장은 폐기했다.

## 4. 배포·자동화

- `build_stats.py`: 비유한 숫자와 달력 불일치를 거부하고 엄격 JSON을 원자적으로 쓴다.
  같은 분 안 재실행도 시각이 아니라 전체 내용을 비교하며, 문서 표식 파손을 실패로 낸다.
- `data_check.py`·`refresh_hist.py`: 0행·날짜·중복·역순·무한대·절대범위·OHLC·열별
  이음새를 막는다. 실행일 기준 신선도까지 통과한 경우만 「이미 최신」으로 인정한다.
  FRED 환율은 실제 공식 `graph/fredgraph.csv`에서 마지막 물리 행 뒤만 붙이며, Yahoo
  예비는 전부 빈 휴장 placeholder와 장중 세션 행을 제거한 확정봉만 쓴다. 수정주가가
  필요한 한국 ETF는 비수정 네이버 자료로 대체하지 않고 KOSPI 지수만 허용한다.
  두 공급원이 죽거나 낡으면 기존 파일을 원자적으로 보존한 채 월간 실행을 실패시킨다.
  기존 CSV의 헤더 순서를 먼저 검사하고, append 전의 물리 바이트는 줄바꿈·숫자 표기까지
  그대로 보존한다.
- `daily-signal.yml`·`monthly-stats.yml`: 허용 산출물만 명시적으로 스테이징하고 추적·
  미추적 잔여 파일을 모두 확인한다. non-fast-forward에서 옛 코드 산출물을 rebase하지
  않고 다음 슬롯 또는 최신 HEAD 재실행에 맡긴다. 일일 알림/장부 이슈 API 장애는 정상
  신호 커밋을 막지 않되 커밋 뒤 실패로 다시 드러낸다.
- `pages.yml`: 봇 push가 새 Pages 실행을 만들지 않는 GitHub 동작을 고려해, 구독한 일일·
  시세 워크플로가 실패로 끝나도 최신 main을 재배포한다. 커밋 뒤 보고 통로만 실패한 경우
  화면이 옛 신호에 멈추는 결합 오류를 막는다.
- `kakao_setup.py`·`kakao_keepalive.py`·`notify.py`·`watchdog.py`: Client Secret ON/OFF를
  모두 지원하고 HTTP 200 안의 실패 본문도 확인한다. 새 refresh 토큰이 발급되면 기존
  토큰은 즉시 무효이므로 자동 저장 실패를 긴급 경고와 실패 상태로 남긴다. 줄바꿈 토큰의
  환경파일 주입을 막고, 셀프테스트는 실제 `GITHUB_ENV`를 오염시키지 않는다. 텔레그램은
  HTTP 성공만 보지 않고 응답의 `ok:true`까지 확인하며, URL에 든 토큰·웹훅은 예외 로그에
  노출하지 않는다.
- `kr_holidays.py`: 2026-05-01 시행 노동절·제헌절 대체휴일, 임시공휴일 충돌,
  GitHub 러너의 UTC와 한국 날짜가 갈리는 연도 경계를 반영했다.
- `price.yml`·`price_poll.py`: UTC 일~목 23시를 KST 월~금 개장 전 슬롯으로 맞춰
  월요일 누락·토요일 오실행을 고쳤고, `--once`도 거래일·장중에서만 돈다. 휴장일 표가
  없거나 범위 밖이면 폴링을 중단하며, 실제 수집 예외를 성공으로 삼키지 않아 연속 3회
  실패 시 현재 실행이 끝나고 다음 예비 슬롯이 이어받는다. `price_now.py`와 공유하는
  저장 경로는 bool·NaN·Infinity를 가격이나 선택 수치로 받지 않고, 완성한 엄격 JSON을
  디스크에 확정한 뒤 원자 교체해 직렬화·부분 쓰기 실패에도 직전 스냅샷 바이트를 보존한다.
- `oos_log.py`·`nav_collect.py`·`signal_alert.py`: 날짜·상태·동결 문턱·QQQ 값·핵심 ETF
  4종·NAV/괴리율과 이미 쌓인 장부까지 쓰기 전에 검증하고, 같은 날짜면 외부 호출보다 먼저
  종료한다. OOS 날짜가 한 번 빠졌더라도 다음 기록의 `changed`는 직전 QQQ 거래일과만 대조해

  가장하지 않는다. 전환 알림은 실제 성공일을 별도 상태에 남겨 같은 날 중복만 막는다.
- `watchdog.py`: 신호·성과·시세의 미래 날짜와 B 상태 손상을 정상으로 숨기지 않으며,
