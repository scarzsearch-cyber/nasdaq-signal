## 1. v56 정정 — 평가창이 서로 포함관계였다

v56 T3 은 결정시점 T 마다 `(T, 2026]` 으로 평가했다. **7개 창이 전부 2026 에서
끝나므로 1985 창이 나머지를 전부 포함한다.** 독립 관측 7개가 아니다.

**겹치지 않게 다시 쟀다:**

| 선택시점 | 뽑힌 규칙 | 평가창 | 이후 선택 | 이후 고정 | 차이 |
|---:|---|---|---:|---:|---:|
| 1985 | −10/−10 | 1986-95 | 4.70 | 5.02 | **−6%** |
| 1995 | −12/−12 | 1996-05 | 18.31 | 29.17 | −37% |
| 2005 | −19/−18 | 2006-15 | 4.30 | 5.50 | −22% |
| 2015 | −19/−18 | 2016-26 | 11.27 | 17.14 | −34% |

**0/4.** 결론은 같지만 **폭이 훨씬 작다**(−6~37% vs 보고했던 −34~96%).
그리고 **독립 관측은 4개**다. 통계적 유의성을 주장할 수 없다는 지적이 맞다.

> **정정 문구**: v56 의 "0/7, −34~96%" → **"0/4, −6~37% (겹치지 않는 창)"**.

## 2. 동결 원칙

```
2026-08-27  규칙 동결
2026-08-28~ 순수 out-of-sample 표본. **평가만 한다.**
```

**`data/freeze.json` 에 적힌 것:**

| | |
|---|---|
| 규칙 | −16/−16 · 룩백 252일 · 전량 전환 · QQQ 미국 종가 |
| 공격 | TIGER 미국나스닥100레버리지(합성) 418660 |
| 방어 | 배당다우존스 40 / 미국채10년선물 40 / KRX금현물 20 |
| 체결 | 전일 미국 종가 → 다음 한국 거래일 (`pos = w.shift(1)`) |
| 비용 | 편도 0.1% + 슬리피지 0.1% |
| 지문 | `0067e42d7aa7c3a3` |

**원칙 (freeze.json 본문에 그대로 들어 있다):**

> 1. 2026-08-28 이후 데이터는 **평가만** 한다.
> 2. 그 결과를 보고 규칙을 수정하지 않는다.
> 3. 수정하면 그 구간도 연구 표본이 되어 순수 OOS 가 사라진다.
> 4. 규칙을 바꾸려면 그 이유가 **동결 이후 데이터와 무관**해야 하고,
> 5. 바꾼 시점부터 OOS 표본을 다시 시작한다.

## 3. 코드로 강제한다

### 3-1. I11 — 매 push 마다 동결 확인

```
I11. 규칙 동결 — 동결 이후는 평가만 한다
  [PASS] 진입선 -0.16                    freeze.json
  [PASS] 복귀선 -0.16                    freeze.json
  [PASS] 룩백 252일                      freeze.json
  [PASS] 신호 생성기가 동결 규칙과 같다        update_signal.py STRATS
  [PASS] 화면이 동결 규칙과 같다             signal.html STRAT.B
  [WARN] OOS 장부가 쌓이고 있다             0영업일 (동결 2026-08-27 이후)
```

**빠른 모드(`--fast`)에 넣었다.** CI 가 매 push 마다 부른다.

**실제로 잡는지 확인했다** — 화면의 복귀선을 −0.15 로 바꾸니:

```
[FAIL] 화면이 동결 규칙과 같다   signal.html STRAT.B
실패 1건
```

**실수로는 못 바꾼다.** 바꾸려면 `freeze.json` 을 **의도적으로** 고쳐야 한다.

### 3-2. 전향적 OOS 장부 (append-only)

`data/signal.json` 은 매일 덮어써서 과거가 안 남는다.
`deploy/oos_log.py` 가 `data/oos_log.csv` 에 하루 한 줄씩 **덧붙인다.**

| 열 | |
|---|---|
| `as_of` `close` `high_252` `dd` | 그날의 관측 |
| `state` `changed` | 동결 규칙이 낸 신호와 전환 여부 |
| `rule` `fingerprint` | 어떤 규칙이 낸 것인지 |

- 이미 있는 날짜는 **건드리지 않는다**(재실행해도 안전)
- 동결일 이전은 **기록하지 않는다**
- **기록만 한다. 어떤 판단도 하지 않는다.**

일일 워크플로에 붙였다 — 매일 자동으로 쌓인다.

## 4. 지금까지의 결론 — 가장 방어 가능한 형태

> **−16/−16 이 전지구적 최적 전략임을 증명한 것은 아니다.**
> 겹치지 않는 어느 구간에서도 1등이 아니다(최고 11위/210).
>
> **그러나 과거 표본에서 선택편향으로 최고 성과 규칙을 골라낸 전형적 패턴은
> 관찰되지 않았다.**
> v18 은 자기 표본의 3위를 골랐고, 시점별 최적 선택 절차는 겹치지 않는 4개 창에서
> 고정 −16/−16 에 **0승 4패**(−6~37%)였으며, 뽑히는 규칙은 −10%~−19% 로 요동쳤다.
>
> **오히려 여러 비중첩 구간에서 최상위 성과를 독점하지 않으면서도
> 최악 구간의 붕괴를 피하는 robust 한 특성이 관찰된다** —
> 6구간 최악순위 126위(미니맥스 **3위/210**), 반면 각 구간 1등들은 146~207위로 무너진다.
>
> **동일한 자료로 선택과 검증을 반복한 것은 사실이고, 관문(4블록·P5·G11)도
> 결과를 본 뒤 만들어졌다. 따라서 선택편향 가능성 자체는 배제할 수 없다.**
>
> **2026년 8월 27일 이후 데이터는 규칙을 동결한 상태에서 순수 OOS 검증으로 보존한다.**

## 5. 앞으로 무엇을 하면 안 되는가

| 하면 안 되는 것 | 왜 |
|---|---|
| OOS 장부를 보고 문턱을 바꾸기 | 그 구간이 연구 표본이 되어 OOS 가 사라진다 |
| "요즘 잘 안 맞네" 로 규칙 수정 | 위와 같다. **최소 몇 년은 쌓여야 한다** |
| I11 을 우회하거나 끄기 | 동결의 유일한 강제 수단이다 |
| freeze.json 을 슬쩍 고치기 | 고치는 순간 OOS 표본이 리셋된다. 그럴 거면 문서에 적어라 |

**해도 되는 것**: 새 연구, 새 후보 탐색, 문서 정정, 화면 개선, 검증 강화.
**동결된 것은 "실제로 굴리는 규칙" 하나뿐이다.**
